v3.0.0 — 31 августа 2026

Адрес ищется по ФИАС прямо в поле

  • Везде, где вводят адрес — быстрое добавление клиента, учётная запись, точка подключения, NAS, коммутатор, объект видеонаблюдения, лид и сделка, — поле стало общим. Раньше подсказки брались только из справочника: если нужного дома там ещё нет, приходилось открывать отдельное окно «Создать через ФИАС».
  • Теперь подсказки приходят и из справочника, и из ФИАС. Найденное помечено: «в базе» — адрес уже заведён, «новый» — будет добавлен при выборе. Отдельное окно больше не нужно.
  • В карточке адреса разбор на составляющие — индекс, регион, район, город, улица, дом, КЛАДР — остался прежним.

Клиента можно найти по договору, телефону и адресу

  • Поля выбора клиента искали по одному названию: чтобы найти человека, надо было помнить, как он записан. Теперь поиск идёт как в строке наверху — по имени, номеру договора, телефону в любом формате, адресу и почте.
  • В подсказке видно то, по чему человека узнают: договор, тариф, адрес, баланс и признак «выключен» — чтобы не открыть однофамильца.
  • Переведены: финансовая операция, объекты, проекты и потоки видеонаблюдения, номера телефонии, параметр отчёта, карточка сделки, привязка тикета и счёта к клиенту, создание обращения.
  • Очередь банковских выписок оставлена со своим поиском: она сверяет ИНН плательщика с операцией и показывает справку ФНС, когда клиента с таким ИНН в базе нет.

Настройка колонок в списках

  • Списки получили кнопку «Колонки»: какие показывать, в каком порядке и какой ширины — настройка сохраняется лично за сотрудником. На телефоне строки показываются карточками.
  • Колонка действий помечена обязательной: её нельзя скрыть или увести с места — иначе строку нечем править.
  • Переведены справочники, списки оборудования, настройки, разделы поддержки и вкладки карточки клиента: услуги, бонусы, лояльность, точки подключения.

Действия строки — одним меню

  • Там, где в строке стояли две-три кнопки-иконки подряд, они собраны в одно меню. На узкой колонке кнопки жались друг к другу, а на телефоне не помещались.
  • Недоступное действие теперь объясняет причину. Например, у системной услуги удаление помечено недоступным: такие услуги ведёт система, вручную их не убирают. Раньше на этом месте стояла кнопка-замок, на которую нельзя нажать.

Пустые таблицы объясняют, что делать

  • Вместо серого «Нет данных» — что именно пусто и что с этим делать: «Операций не найдено. Попробуйте изменить период или снять фильтры», «В тарифе пока нет услуг. Добавьте услугу — из них складывается абонплата».
  • Раньше одна и та же надпись стояла и когда записей ещё не заводили, и когда фильтр ничего не нашёл.

Меньше повторов на страницах

  • Со страниц убраны собственные заголовки, повторявшие название раздела в шапке, лишние значки документации и счётчики записей рядом с числом строк под ними. Значок остаётся один, в шапке раздела; подсказки внутри диалогов сохранены — там они объясняют поля формы.
  • Журнал операций больше не отдельная страница: он показывал те же данные, что и отчёт «Платежи», с теми же фильтрами и итогами. Старый адрес ведёт в отчёт.

v3.0.0 — август 2026

Защита от дублей клиентов

  • Система больше не даёт создать второго клиента с тем же номером договора — ни через быстрое добавление, ни через полную форму, ни из сделки CRM. Договор — фактический уникальный идентификатор клиента. При повторном номере показывается ссылка на существующего клиента, дубль не создаётся. Сравнение учитывает ведущие нули (EBS-договора). Папки не проверяются.

MAC оборудования редактируется в таблице аккаунтов

  • Колонка «Mac девайса» на карточке клиента (вкладка «Аккаунты») стала редактируемой прямо в таблице: карандаш или двойной клик → поле ввода → сохранение. Формат MAC проверяется, при совпадении с MAC другого клиента показывается предупреждение. Значение общее для клиента — правка обновляет все строки.

AI-бот: телефон поддержки берётся из брендинга организации

  • Телефон, который AI-ассистент даёт клиентам, теперь берётся из Настройки → Организации → Брендинг → «Телефон поддержки» (свой у каждой организации), а не из зашитого в код значения. Пусто — бот предлагает написать оператору без диктовки номера.

Склад: роли «держателей подотчёта»

  • «Взять со склада» (взять единицу себе в подотчёт) в скан-центре доступно сотрудникам из групп-держателей (настройка STOCK_HOLDER_GROUPS, по умолчанию установщик / поддержка / кладовщик), а также кладовщикам и суперпользователям. Если группа сотрудника не в списке — сообщение «Ваша группа не входит в держателей подотчёта». Список групп настраивается без правки кода.

СОРМ: изоляция по организации и мобильная версия (UX-аудит)

  • Мульти-орг изоляция по прямой ссылке: открыть, запустить или удалить чужой СОРМ-конфиг по прямому URL больше нельзя — проверяются права сотрудника (allowed_orgs). Список тоже скоуплен по правам. Подробнее — Мульти-организация.

Вкладка «Развёртывание» в карточке NAS позволяет управлять конфигурацией MikroTik и другого оборудования. Полностью воспроизводит функционал Carbon Billing 4.

Общая схема работы

1. Инициализация    → rtsh cfg init <scheme>   → создаёт структуру каталогов
2. Заполнение данных → rtsh cfg fill <ip>       → заполняет .ini из биллинга
3. Скачать текущую   → rtsh cfg download        → загружает конфиг с оборудования
4. Генерация новой   → rtsh cfg make            → генерирует .cfg из .ini + .tmplt
5. Загрузка          → rtsh cfg upload          → загружает конфигурацию на NAS
6. Сохранение        → rtsh cfg save            → коммит в git-историю

rtsh cfg init <scheme_name>  — инициализировать каталог управления
rtsh cfg fill <ip>          — заполнить .ini данными из биллинга
rtsh cfg make               — сгенерировать конфигурацию из .ini + .tmplt
rtsh cfg upload             — загрузить конфигурацию в оборудование
rtsh cfg download           — скачать конфигурацию с оборудования в ./cur/
rtsh cfg save <comment>     — сохранить в git-историю
rtsh cfg diff [ref]         — показать изменения
rtsh cfg status             — текущее состояние
rtsh cfg log                — журнал изменений
rtsh acl upload             — загрузить ACL-листы на оборудование
rtsh list scheme            — список доступных схем

Docker конфигурация

  • Dockerfile — COPY oss_tools/ (rtsh, oss_bin, oss_share) + apt install git rsync
  • Volume oss_data:/var/oss — данные сохраняются между перезапусками
  • /run_script/ — endpoint для выполнения команд (POST → start, GET → stream stdout)
  • Gunicorn — WORKERS=1, THREADS=8 (для корректной работы /run_script/)

Аудит форм — Select2 и AJAX

Все FK-поля всех форм биллинга проверены и оптимизированы:

  • Select2 — для справочников до 100 записей (NAS, типы авторизации, IP-пулы)
  • AJAX Select2 — для больших справочников (Homes: 4270 записей — поиск по адресу)
  • Popup-select — для таблиц > 500 записей (клиенты, пользователи)
  • HEAVY_FK_FIELDS — ограничение queryset для таблиц > 1000 записей
